# DevOps Infrastructure Status Dashboard

Учебный дашборд статуса инфраструктуры в стиле Grafana/Datadog. Backend на Express считает запросы и хранит лог событий в Redis, frontend на чистом HTML/CSS/JS опрашивает REST API каждые 3 секунды и обновляет карточки серверов, KPI и таблицу логов.

## Стек

- **Backend:** Node.js, Express, [ioredis](https://github.com/redis/ioredis)
- **Frontend:** чистый HTML5, CSS3, JavaScript (Fetch API), без фреймворков и сборщиков
- **База данных:** Redis (счётчик запросов, лог событий, снапшот статусов серверов)

## Требования

- Node.js 18+
- Запущенный Redis (локально, в контейнере или удалённый)

## Переменные окружения

Скопируйте `.env.example` в `.env` и при необходимости отредактируйте:

```
PORT=3000
REDIS_HOST=localhost
REDIS_PORT=6379
NODE_ENV=development
```

| Переменная  | По умолчанию | Назначение                        |
|-------------|--------------|------------------------------------|
| `PORT`      | `3000`       | Порт, на котором слушает Express   |
| `REDIS_HOST`| `localhost`  | Хост Redis                         |
| `REDIS_PORT`| `6379`       | Порт Redis                         |
| `NODE_ENV`  | `development`| Окружение (информационно)          |

Приложение читает эти переменные напрямую из `process.env` — `.env` файл не подгружается автоматически (dotenv не используется), так что либо экспортируйте переменные в shell, либо передавайте их при запуске.

## Установка и запуск

```bash
npm install

# локально, если Redis уже запущен на localhost:6379
npm start

# либо явно указав параметры
PORT=3000 REDIS_HOST=localhost REDIS_PORT=6379 npm start
```

Если под рукой нет установленного Redis, быстрый вариант для локальной проверки:

```bash
docker run --rm -p 6379:6379 redis:7-alpine
```

После запуска дашборд доступен на `http://localhost:3000`.

## API

| Метод | Путь            | Описание                                                        |
|-------|------------------|-------------------------------------------------------------------|
| GET   | `/`              | Отдаёт `public/index.html`                                       |
| GET   | `/health`        | `{ status, redis: "connected"/"disconnected", uptime }`          |
| GET   | `/api/metrics`   | Метрики системы, статусы серверов, счётчик запросов, лог событий |

`/health` рассчитан на использование как Docker `HEALTHCHECK` в будущем.

## Как это работает

- Каждый входящий HTTP-запрос логируется в stdout в формате JSON (удобно читать через `docker logs`) и инкрементирует счётчик `infra:request_count` в Redis.
- Фоновый процесс раз в 4 секунды обновляет статусы серверов (`infra:servers`) и добавляет случайное событие в лог (`infra:logs`, список на 50 последних записей) — это симулирует реальную телеметрию для учебных целей.
- При недоступном Redis сервер не падает: `/health` и `/api/metrics` возвращают `redis: "disconnected"` и дефолтные значения, счётчик запросов просто не обновляется.
- Обрабатываются сигналы `SIGINT`/`SIGTERM`: сервер закрывает HTTP-соединения, останавливает фоновый таймер и корректно закрывает соединение с Redis (graceful shutdown с принудительным завершением через 10 секунд, если что-то зависло).
